# BrokenEngineSandbox Client Commands

[Back to AgentHarness hub](../AgentHarness.md)

### Client commands

- `client_subscribe_accept_fixture`: isolated Debug-only coverage of the real client branch for an invalid non-sentinel subscribe-accept slot. The schema is exactly `{"slot":int}`. It requires an accepted connected client and `clientCoordSlots <= slot < 255`. The command serializes and synchronously injects a valid accept with epoch zero and coord `[0,0]`; the production branch serializes its ordinary cleanup unsubscribe, while a scope guard suppresses that fixture's send. It returns `{"slot", "outOfRange":true, "cleanupSerialized", "cleanupSlot", "cleanupSize", "networkSendSuppressed":true}`. Require the existing `Client::ServerSubscribeAccept Out-of-range` log, `cleanupSerialized:true`, `cleanupSlot == slot`, `cleanupSize == 4`, and a connected client. This fixture covers only the initial client branch and serializer; it makes no claim about server cleanup, an ACK, or end-to-end preservation.
- `client_stale_update_fixture`: exact empty-object Debug-only command that captures the next actual accepted ordinary server coord update, waits until its slot, epoch, coord, ACK floor, and confirmed tick make that update stale, then re-delivers the exact bytes on the earliest subsequent poll after disconnect/load handling and immediately before the ordinary receive drains. The one response is deferred; no arm, inspect, clear, or delay action exists. It returns `coord,slot,epoch,tick,capturedBytes,ackFloorBefore,ackFloorAfter,confirmedBefore,confirmedTick,retainedUpdate,connected`. Require positive `capturedBytes`, unchanged ACK floor, `confirmedTick >= confirmedBefore >= tick`, `retainedUpdate:false`, and `connected:true`. Start a second request and reset the server to verify the normal failure envelope names the server load reset; the copied bytes are released on reset. Capture plus readiness is bounded by 128 client polls and reports its own expiry, while the command transport keeps its ordinary outer generation and drain timeout.
- `client_cancelled_subscription_fixture`: Debug-only accept-after-cancel coverage with exact schema `{"coord":[x,y]}` and coordinate values within `+/-1000000`. It requires an accepted connected client with an assigned player, a coord absent from active slots and desired/sticky/queued subscription policy, and a clean unsubscribed local slot. The fixture fabricates only that local subscribing slot, calls the production cancellation method, injects a valid accept, and sends the production unsubscribe. Its single response remains deferred until the real server ACK retires the slot. It returns `coord,slot,initialState,afterCancelState,afterAcceptState,subscribingToUnsubscribed,acceptToUnsubscribing,policyUnchanged,ackRetired`; require the states to be `subscribing`, `unsubscribed`, `unsubscribing`, every boolean true, and the existing `Client::ServerSubscribeAccept Cancelled` log. Replacement, disconnect, an unexpected slot state, or no ACK within four seconds returns the normal failure envelope. This fixture covers accept-after-cancel only and does not induce full-state-first ordering.
- `client_packet_fault_fixture`: client-fatal corruption fixture. The schema is exactly `{"case":"engine_envelope"|"status_change"|"game_packet"}`; extra, missing, or non-string fields fail. Requires `kbDebugInput` (it deliberately ends the process) and a connected client, and fails while a packet is already armed. It does not inject during the command: `AgentCommandServer::Drain` catches every handler exception, which would swallow the assertion, so the command arms one malformed server-to-client packet, answers `{"case":string,"type":int,"size":int,"armed":true}`, and the packet is delivered later the same frame from the client main loop, outside that catch. The client then logs `Client::Receive dropped corrupt packet (type N)` (or `ClientSession::ProcessReceivedGamePackets dropped corrupt player-event packet` for `game_packet`) and asserts, so the process exits and writes a crash report containing `Assert failed:` plus that log line. A `kWarning` line with the client still running is the failure signal.

  | Case | Packet | Bytes | Reader that rejects it |
  |------|--------|-------|------------------------|
  | `engine_envelope` | `PacketType::kServerCoordFullState` | 3 | `NetworkMessages::Read` — the envelope's fixed fields run past the end |
  | `status_change` | `PacketType::kServerCoordUpdate` | envelope + 8 | `DecompressStatusChangeBatch` — out-of-range uncompressed-size prefix |
  | `game_packet` | `GamePacketType::kServerAssignPlayer` | 2 | `ParsePlayerEvents kServerAssignPlayer` — payload size mismatch |

  `status_change` additionally requires an active coord slot, whose index and epoch it copies so the packet passes slot classification and reaches the status-change decoder; its echoed timestamp is zero so no RTT or jitter smoothing state is written before the throw.
- `client_full_state_fixture`: `{"action":"arm_stall"|"inspect"|"exercise_gap"|"exercise_matching_tick"|"clear"}`. `arm_stall` requires connected confirmed state and returns `{"clientTick","stalled","desyncTick","syntheticStall","armedTick","timeMultiply","timeDivide","coordState":...}`. `inspect`, `exercise_gap`, and `exercise_matching_tick` fail with `client_full_state_fixture is not armed` unless `arm_stall` ran first; `inspect` otherwise returns the same live shape. `clear` runs before that armed check, so it is the reader to use for live `timeMultiply`/`timeDivide` on an unarmed client. `clear` idempotently clears synthetic stall and returns that shape with `syntheticStall:false,armedTick:-1`. A present coord state is `{"coord":[x,y],"present":true,"confirmedTick","confirmedOffset","highWaterValidatedTick","lastFullStateTick","snapshotHead","snapshotCount","lastRenderedTick","lastRenderedTime","serverUpdateCount","lastReplayConfirmedTick","lastReplayServerUpdateCount","stuckFrameCount","pendingFullStateTick":int|null,"firstServerUpdateTick":int|null,"lastServerUpdateTick":int|null,"ringValid","tailTick"}`; absent state contains only coord and `present:false`. `exercise_gap` returns `pendingTick,deferTargetTick,beforeDefer,afterDefer,deferPendingPreserved,deferDesync,removedUpdateCount,uncappedConsecutiveEndpoint,directAdoptionRequired,adoptionDesync,afterAdoption,pendingCleared,adoptedTicksMatch,confirmedOffsetZero,obsoleteUpdatesAbsent,ringHeadIsAdopted,directAdoptionProven,renderBaseNotOlderThanLastRendered,cleared`. `exercise_matching_tick` keeps the updates contiguous so the pending full-state tick is the replay endpoint, fails when any update from `confirmedTick+1` through that tick is missing (retry after more updates arrive), and returns `pendingTick,deferTargetTick,beforeDefer,afterDefer,deferPendingPreserved,deferDesync,injectionDesync,afterInjection,pendingCleared,headTick,confirmedTick,confirmedOffset,cleared`.
- `desync_probe`: packet mode `{"desyncReports"?:0..8,"debugFrameRequests"?:0..8}` or mutually exclusive recovery mode `{"triggerRecovery":true}`. Requires connected in-game current state. Returns `{"tick","coord":[x,y],"desyncDebugFrames","stalled","desyncReports","debugFrameRequests","triggerRecovery"}`.
- `set_client_grid_coord`: `{"coord":[x,y]}`. The object accepts only `coord`, an array of exactly two integers with `|value| <= 1000000`. Moves the client's grid cell and immediately refreshes its desired subscriptions, so automation can drive the cross-cell subscribe and full-state adoption path. Requires a connected client with a valid assigned player. Returns `{"clientGridCoord":[x,y]}`. Any invalid input returns the normal `ok:false`/`error` envelope and changes no state. The coordinate is transient agent input: the game overwrites it on player events and fleet synchronization at any time, and it is never persisted, so poll immediately after the command. The server remains the subscription authority — a non-adjacent cell is accepted locally and rejected on the wire (see [Cross-cell subscription verification](cross-cell.md#cross-cell-subscription-verification)).
- `screenshot`: `{"path"?,"maxWidth"?:1568,"format"?:"jpg"|"png","quality"?:80}`. Quality range is `1..100`. A `maxWidth` value `<= 0` disables downscaling and preserves native framebuffer dimensions. Default path is `%TEMP%\Screenshots\agent_N.<ext>` using the process temp directory. Returns `{"path","width","height"}` — the saved file and its pixel dimensions, never image bytes. Requires `kbScreenshots`.
- `renderdoc_capture`: `{"frames"?:1}`; `frames` is `1..8`. Triggers RenderDoc capture(s) of the next presented frame(s) and returns `{"paths":[absolute .rdc paths]}`. Requires a client launched with `--renderdoc`; otherwise returns `ok:false` naming `--renderdoc`. Temporarily restores a minimized client without activation, captures, then re-minimizes; an already-visible client fails when swapchain recreation is deferred. Occupies the single channel until RenderDoc has serialized every capture. The wait is bounded by the deferred-response drain-count liveness timeout (`kiDeferredTimeoutDrains` drains, counted once per client render frame), not wall-clock, so set `--timeout-ms` at least as large as the expected wall-clock capture time. See [RenderDoc capture](../../../../.agents/skills/agent-harness/references/renderdoc.md).
- `resize`: `{"width","height"}` within `320x180..16384x16384`; rounds each to 8, then returns OS-applied `{"width","height"}`. Rejects while minimized and never changes persisted/fullscreen state.
- `fullscreen`: `{"on":bool}`. Toggles borderless fullscreen/windowed without persisting. Windowed restore uses launch extent, not a later resize. Returns `{"fullscreen","width","height"}`. Rejects while minimized.
- `window_state`: `{"minimized":bool}`. Minimize uses normal minimize; restore does not activate and waits for settled swapchain. Returns `{"minimized","width"?,"height"?}`.
- `audio_resume`: no params. Resumes client audio; an agent client boots with audio suspended, so send this before any scenario that must observe audio. Completes synchronously with the normal envelope; repeating it is accepted.
- `dump_render_target`: `{"name","index"?:0,"channel"?:0,"path"?,"raw"?:false}`. Unknown names list valid names. Single-channel output normalizes to grayscale PNG; four-byte RGBA writes direct PNG; float formats require raw `.bin`. The default base path is `%TEMP%\Screenshots\dump_<name>_N`. Requires `kbScreenshots`.
- `describe_ui`: no params. Returns UI state, `tweaksVisible` (true while the F3 Tweaks overlay is shown), game flags, framebuffer, mouse, windows, and labeled items with rect/disabled/checked/inputable/hovered/visible fields. Menu controls created with `MenuUtils::WrapperSlider` and `MenuUtils::WrapperPlusMinus` also include optional `value` text for the current numeric value, using the control's display format. Other items omit the field; checkbox state and radio controls created with `MenuUtils::RadioRow` expose their state through `checked`.
- `click`: `{"label","window"?,"timeoutFrames"?:120,"describeUiAfter"?:true}`. Stabilizes and clicks the item center. Returns found/enabled and optional UI. Ambiguous/not-found errors list candidates; scrolled-out targets fail.
- `hover`: `{"label","window"?,"holdFrames"?:2}`. Returns found/enabled plus UI.
- `set_slider`: `{"label","window"?,"value":number}`. Uses Ctrl+Click, typing, Enter. Returns found/enabled.
- `key`: `{"key":name,"holdFrames"?:1}`. `holdFrames` is an integer in `0..1798` (default `1`); signed negative values normalize to `0`. The limit counts client drains/frames rather than wall-clock time, so duration varies with the client drain rate. Supports case-insensitive single letters/digits; `ESC`/`ESCAPE`, `SPACE`, `TAB`, `ENTER`/`RETURN`, `UP`/`DOWN`/`LEFT`/`RIGHT`, and `F1`–`F24`. Returns `{"ok":true}`.
- `mouse`: `{"action"?:"move"|"down"|"up"|"click"|"wheel","x"?,"y"?,"button"?:"left"|"right"|"middle","notches"?:1}`. Non-wheel actions require x/y. Wheel accepts both coordinates or neither and always feeds the ImGui wheel event. It also feeds camera zoom unless the hovered ImGui window can actually scroll, ImGui's wheeling lock holds an earlier scroll target, or an ImGui key owner claims `ImGuiKey_MouseWheelY` (including ImPlot); menus that do not scroll still zoom the camera. ImPlot ownership remains visible for the first two input polls after leaving a plot; the following poll first sees no owner. A coordinate mouse move runs two active frames and, once complete, establishes the new target. A direct coordinate-bearing background wheel immediately after plot hover may remain UI-owned; a subsequent notch after that command completes reaches the camera. Returns `{"ok":true}`.
- `describe_scene`: `{"includeUnits"?:true,"maxUnits"?:200,"unitTypes"?:["player","spaceship","blaster"]}`. `unitTypes` is an array of those three strings; absent means every type, an empty array emits no unit rows, and any other value or unknown string is a parameter error. It applies only when `includeUnits` is true. Returns `camera{eye,visibleArea,lod}`, `uiState`, `tweaksVisible` (true while the F3 Tweaks overlay is shown), `gameFlags`, `tick`, `clientGridCoord`, `subscribedCoords`, `fleets[{index,focused,members?}]`, `units[{type,globalId?,world,screen,armor?,shield?,health?,alignment,flags?,windTrailIntensity?,windTrailWidth?,windTrailLengthMultiplier?}]`, cell-wide `counts{players,spaceships,missiles,blasters}`, `islands[{coord,center,rotation,footprint?}]`, and `truncated`. Blaster rows carry the three `windTrail*` fields and no `flags`. Unit positions come from the committed snapshot and trail rendered pixels.
- `query_profile`: no params (only an empty object is accepted). Client-only GPU profile query; returns `gpuTimers[{index,name,currentUs,averageUs,maxUs}]` for every timer row, including zeros, and frame-coherent `shadowSample{sequence,currentUs}`. The sample is published after the matching framebuffer fence; sequence advances only when a new available Shadow result is latched.

### Client command behavior

Client input/capture commands can defer across frames. The single channel remains occupied until the response; size timeout accordingly and never overlap calls.

For `client_full_state_fixture`, keep the accelerated stall under 256 buffered ticks per coord (`coordState.serverUpdateCount` from `inspect`): at that limit the client requests a full-state resync and resets coord state, discarding the pending full state and confirmed ticks `exercise_gap` needs. Run `arm_stall`, accelerate the server, then `inspect`. Require unchanged client/armed tick, changed timescale, and a pending full-state tick above client tick. Run `exercise_gap`; require both desync fields false, pending preservation, `uncappedConsecutiveEndpoint < pendingTick`, direct adoption required/proven, pending cleared, adopted ticks match, confirmed offset zero, obsolete updates absent, ring head adopted/valid, and render base not older than last rendered. `removedUpdateCount` may be zero. Always `clear` interrupted setup.

Capture commands temporarily restore a minimized client without activation, wait for extent settlement, capture, then re-minimize. An already-visible client fails if swapchain recreation is deferred. `resize`/`fullscreen` reject minimized state; restore first. After resize/fullscreen/restore, call `describe_ui` or `screenshot` to remeasure.

Only labeled visible ImGui items are addressable. Scroll a clipped container with `mouse` wheel, then retry. `describe_scene.units` are visible-area-filtered while counts span subscribed cells; edge projection may lie slightly outside the framebuffer. Only players have global IDs, and only the focused fleet lists members. Each cell emits its blaster rows after its player and spaceship rows, while the `maxUnits` cap is shared across all subscribed cells.

Injected mouse position owns `io.MousePos`: a coordinate-carrying script such as `hover`, `click`, or coordinate-bearing `mouse move` pins an ImGui mouse position from when that script issues it until the next accepted script begins. A later coordinate-free script such as `key` clears the pin; after that, `describe_ui.mouse` reports ImGui's no-mouse sentinel, and a coordinate-free `mouse wheel` does not target the previous pixel. Send wheel coordinates explicitly; do not rely on a pin surviving an intervening script. With no pin, a focused agent client's `describe_ui.mouse` reports ImGui's no-mouse sentinel rather than the real cursor, and the RawInput game mouse stays at a frozen boot-time snapshot (under agent suppression, physical mouse messages never reach DirectXTK Mouse).

## Durable caveats

- When comparing `query_profile` timings, run and discard a warm-up cohort first, take baselines only after values settle, and compare cohorts of equal sample count captured within one process lifetime. For the server `NavQuery` raw row, retain every observed sequence and gap marker, then qualify cohorts only from records with `queryCount == 8 && aStarCount == 8`; do not reconstruct skipped sequences or use the overlapping `averageUs`/`maxUs` smoother rows as cohorts.
- Client capture/input/UI/GPU `query_profile` commands live in `Engine/Source/Agent/AgentCommandsClientGeneric.cpp`; the client full-state fixture, desync probe, grid-cell move, and client dispatch live in `AgentCommandsClient.cpp`, and scene commands live in `AgentScene.cpp`.
