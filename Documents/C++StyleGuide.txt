Use the following rules for C++ code

1. Use tabs for indentation	

2. Curly braces go on the next line for functions, scopes, and lambdas. A multiline struct or class initializer puts its opening brace on the next line. A complete single-line initializer can keep its braces on the declaration line.

	if ()
	{
	}

	auto GetContent = [](const auto& rSource) -> std::pair<bool, std::string>
	{
	}

	Widget widget
	{
		.value = 1,
	};

	Widget emptyWidget {};

3. Hungarian notation

	Constexpr - k: inline constexpr float kfMinDepth = 0.0f;
	Enum declaration - k: enum class TextureFlags { kMultisampling = 0x01, kRenderPass = 0x02, };

	Static - s: static bool sbQuit = false;

	Global - g: inline Graphics* gpGraphics = nullptr;
	Member of a class - m (classes only, not structs): bool mbQuit = false;

	Pointer - p: IXAudio2SourceVoice* pVoice = nullptr;
	Reference - r: const game::MenuInput& rMenuInput

	character - c: char cChar = 'a';
	integer - i: int64_t iCount = 0;
	unsigned integer, unsigned short, byte - ui: uint16_t suiMax = 0;
	boolean - b: bool bEnabled = true;
	enum variable - e: CpuCounters eCpuCounter
	Vulkan type (any Vk* type, including Vulkan enums, which take vk instead of e, and integer typedefs such as VkDeviceSize and VkBool32; after another prefix it is written Vk, and class members follow rule 54) - vk: VkBuffer vkBuffer; VkResult vkResult; VkBuffer& rVkBuffer; VkImage* pVkImage; inline constexpr VkFormat kVkFormatDepth
	float, double - f: float fVolume = 1.0f;
	XMFLOAT[2/3/4] - [f2/f3/f4]: XMFLOAT2 f2MousePosition {};
	XMVector - vec: XMVECTOR vecPosition {};
	XMMatrix - mat: XMMATRIX matWorld {};

	std::string and std::string_view - no hungarian prefix
	
4. Use "#pragma once" for header guards: #pragma once

5. Use RAII for allocations and locking: std::unique_ptr<game::Frame> mpCurrentFrame;

6. Features are toggled via `inline constexpr bool kb*` variables in Pch.h (e.g., kbLogging, kbRecording). Use `if constexpr` for conditional compilation. Avoid using configuration differences directly (BT_DEBUG vs. BT_RELEASE):

	if constexpr (kbLogging)
	{
		Log("message");
	}

7. Camel case, except for template parameters. Classes and functions start with an uppercase letter, variables start with a lowercase letter. A variable holding a lambda or a std::function is named like a function, starting with an uppercase letter, or continuing uppercase after a rule 3 prefix (mGetNextTrack, rWriteBody): auto Sample = [&](int64_t iFrame) -> float { ... }; called as Sample(i).

	class RenderThread
	constexpr uint32_t kuiThreadCount
	template <typename T> or template <typename... TUV>

8. Use i/j/k variable names in for loops, but prefer range-based for loop when possible. When a counter is the zero-based ordinal of every visited element, std::views::enumerate with a structured binding is recommended over a counter initializer statement, which remains allowed; the element's reference and constness come from the underlying range, so enumerate a const range for read-only access. If any other counter variable is required with a range-based for loop, use the C++20 syntax to include an initializer statement. Use "it" for iterators.

	for (int64_t i = 0; i < std::ssize(mIslands); ++i)
	for (auto [i, rMember] : std::views::enumerate(pFleet->members))

9. Exceptions are for fatal errors only (things that would cause the program to crash), not control flow. Use standard-library exception types by default. Define a custom exception only when it adds useful functionality, such as concrete data or behavior; do not add an empty derived type merely to rename or categorize a failure.

10. "/" for header include paths, not "\\": #include "Graphics/Graphics.h"

11. Use C++-style casts, static_cast reinterpret_cast etc...: static_cast<data::DataTypes>(i). For an intentionally discarded non-void function result, use std::ignore = call(); rather than a cast to void; retain required result checks.

12. For duration and time use std::chrono, use chrono_literals suffixes for example:
	Nanoseconds - std::chrono::nanoseconds durationNanoseconds = 10ns;
	Microseconds - us
	Milliseconds - ms
	Seconds - std::chrono::seconds seekSeconds = 1s;

13. Default to int64_t: int64_t iCount = 0;
    -Use int8_t, int16_t when packing into structs and arrays (if higher range of larger types is not required)
	-Use unsigned integers when doing bitwise operations
	-Use the corresponding type when dealing with directly with parameters and return values from other APIs (ex: Vulkan uses uint32_t)

14. Use "Count" not "Num", ex: uint32_t kuiThreadCount = 3; not kuiNumThreads

15. YOU MUST not use auto keyword unless:
	a) It's an XMVECTOR or XMMATRIX: auto vecResult = XMVector3Normalize(vecInput);
	b) The type is obvious from a template parameter to the right
	c) It is an iterator
	d) It is a structured binding: auto [it, bInserted] = map.try_emplace(key, value);
	e) It is a lambda expression assigned directly to the variable: auto Callback = []() {};
	f) It is a generic lambda parameter: [](const auto& rSource) {};
	g) It is an explicit object (this auto&&) or abbreviated-template (auto&&) parameter, and the deduced return type, of a function returning a std::tie member list: auto SharedMembers(this auto&& rSelf) { return std::tie(rSelf.a, rSelf.b); }

IMPORTANT do not use auto in range-based for loops, except for the structured binding of rule 8 enumeration or rule 38 associative-container iteration

16. Never use operator[] on std::unordered_map/std::map — it silently inserts a default-constructed value when the key doesn't exist, which can mask bugs. Use these safe alternatives:

	Read: map.at(key)
	Write/assign: map.insert_or_assign(key, value)
	Create-then-use: map.try_emplace(key).first->second
	Ensure existence: map.try_emplace(key);

	Access std::vectors with .at(): mIslands.at(0).quad

17. Use int64_t (rule 13) for std::vector sizes and indices, obtaining the size with std::ssize(), unless the value's consumer requires another integer type (an API parameter or serialized field type): for (int64_t i = 0; i < std::ssize(vec); ++i)

18. Use "const" for read-only reference and pointee contracts:
	a) A pointer or reference is passed into a function and not modified: const game::MenuInput& rMenuInput
	b) A reference in a ranged for loop is not modified: for (const Island& rIsland : mIslands)
	Do not add top-level "const" to local value variables. Use a normal variable for runtime values, or follow rule 25 for compile-time constants.

19. Use "typename" not "class" for template declarations, template parameters should be in all upper case ex: template <typename T, typename... TUV>

20. Use uniform initialization only for structures, arrays, and initializer list constructed classes
	int i = 0;
	Class class(0, i);
	Struct struct {a = 0, b = i};

21. Prefer std::span<const T> (or std::span<T> for writable views) over pointer + size parameter pairs: void Receive(std::span<const uint8_t> packetData). Span parameters take no Hungarian prefix (packetData, crcs, buffer). C arrays remain fine for fixed-size storage; std::array is acceptable where value semantics or aggregate initialization help. Don't use std::bitset — use common::Flags or integer bitfields. (Engine, DataPacker, and ThirdParty Debug configs pin _ITERATOR_DEBUG_LEVEL=0 and STL hardening off, so span operator[]/iterators have no bounds checks in any config.)

22. Have a comma at the end of every line in initializer lists

	int pInts[] =
	{
		1,
		2,
	};

23. Use 'using' keyword instead of typedefs: using MenuFlags_t = common::Flags<MenuFlags>;

24. Normalized XMVECTORs should be postfixed with "Normal", a postfix of "Direction" also implies that it is normalized: XMVECTOR vecSunNormal, XMVECTOR vecDirection

25. Use "static constexpr" at function scope, "inline constexpr" at global scope in headers

	static constexpr float kfNoonStart = XM_PIDIV8;  // function scope
	inline constexpr float kfMinDepth = 0.0f;  // global scope in header

26. Avoid overuse of "using enum", try to only use on enums in direct header: using enum MenuFlags;

27. Floating point constants should always have the decimal and first digit, even if it's 0. Only float constants have 'f' appended; double constants never do: float fValue = 1.0f; double fSeconds = 1.0;

28. Use nullptr instead of NULL: IXAudio2SourceVoice* pVoice = nullptr;

29. Use override keyword on child class virtual functions: void Update() override;

30. No space on ">>" ex: std::vector<std::vector<float>>

31. Use static_assert instead of runtime assert whenever possible: static_assert(std::chrono::high_resolution_clock::is_steady);

32. Use std::unordered_map instead of std::map: std::unordered_map<common::crc_t, Texture> mTextureMap;

33. Do not use any constants from limits.h, instead use std::numeric_limits: std::numeric_limits<float>::max()

34. Use digit separators for large numbers: uint32_t uiOneMillion = 1'000'000;

35. Use the file system library std::filesystem

36. Always initialize variables (unless it is a class with a constructor). Use inline variables with initializers in header (both globals and class members). Do not initalize class member variables in the .cpp file.: bool mbQuit = false;

37. Use structured bindings for multiple return from functions with std::tuple<>: auto [bMultisampling, bPrevious, bChanged] = gMultisampling.Changed<bool>();

38. Use structured bindings in range-based for loops over associative containers (std::map, std::unordered_map)

	for (const auto& [rCrc, rTexture] : mTextureMap)
	{
		crcs.push_back(rTexture.mInfo.crc);
	}

39. Use [[maybe_unused]] when a variable is unused: void Func([[maybe_unused]] int64_t iUnused)

40. Use std::string_view or std::wstring_view instead of "const char*" or std::string& or std::wstring& parameters into functions; a "const char*" or "const wchar_t*" parameter stays when a caller can pass null or when its value reaches an API that needs a null-terminated string: void UpdateTextArea(TextAreas eTextArea, std::string_view pcCharacters); bool BeginSubtab(const char* pcLabel, int64_t iSection, int8_t iTab);

41. Explicitly use std:: namespace, do not `using namespace std;`: std::vector, std::string, std::unordered_map
NOTE: The following global namespaces are allowed: `using namespace DirectX;`

42. Use designated initializers for struct initializers: LazyChunk { .location = loc, .header = chunkHeader, }

43. Run-Time Type Info (RTTI) is disabled, do not use it

44. Prefer aligned data for "DirectX Math": XMStoreFloat4A is better than XMStoreFloat4

46. Do not use Est (estimate) functions in "DirectX Math", they may have different behaviour on different architectures: Use XMVectorReciprocal(), not XMVectorReciprocalEst()

47. Header include order (groups separated by exactly one blank line, no blank line inside a group):
	a) Corresponding .h file (always first; only a leading "Pch.h" include precedes it)
	b) engine:: includes: headers resolving under Engine/, Common/, DataPacker/ or Tools/, and generated Data/ pack headers
	c) game:: includes: headers resolving under Projects/
	d) External C++/platform headers, only in projects without a precompiled header (Tools/); elsewhere external and common:: headers go in Pch.h
	Within each group, compare paths one folder level at a time: at each level folders sort before files, then alphabetically (case-insensitive)
	Includes inside an #if block that is not a whole-file guard keep their hand order

48. Don't add extra curly brackets for scope to force close std::fstream, instead use .close() when no longer needed: fileStream.close();

49. Class state is public by default and is read or mutated directly. Do not add getter, setter, drain, take, `Is*`, `Can*`, or other accessor methods for independently readable or mutable state. Do not add a function whose implementation is only one state access, one assignment, or one pass-through call; spreading its braces and statement across several lines does not make it acceptable. Put the member or composed component in `public:` and perform the operation at the caller.

	`protected:` and `private:` are reserved for state whose members must be mutated together to preserve an invariant or operation order. The function protecting that state must contain the complete multi-statement mutation; a trivial accessor or forwarding layer is never justified. This rule targets state access and pass-through APIs, not a semantic codec or serialization adapter whose call defines the layer contract.

50. if () statements compare booleans they don't take pointers:

	if (pPointer != nullptr)
	{
	}

51. Keep function parameters AND arguments all on the same line, regardless of line length. This applies to BOTH function declarations and function call sites. Never split a call's arguments across multiple lines just because the line is long — long is fine. The only exception is when an argument is itself a lambda body or a struct/initializer-list literal that spans several lines, in which case the `{}` goes on the next line per rule 2 (and the other arguments still stay on the call line). A braced initializer list written on one line stays on the call line like any other argument.

	The same goes for every other statement: never split a declaration, assignment, return, or other expression across lines just because it is long — long is fine. The codebase's established multi-line forms stay: a lambda body or multi-line struct/initializer-list literal (rule 2, rule 22, and the exception above), a Boolean expression past 140 columns under the threshold below, a constructor's member-initializer list written one initializer per line, a macro body continued with trailing backslashes, a long string built from adjacent string literals written one literal per line, a concept's constraint expression starting on the line after its "=", a template head (the template-parameter list) on its own line before its declaration, and a template's requires clause on its own line. Anything else is a judgement call — you'll know a random split when you see it.

	Ordinary Boolean expressions follow a length threshold instead: a Boolean assignment or initializer, an if()/while() condition, or a returned Boolean expression that joins onto one line of 140 columns or fewer stays on one line — never split it at && or ||. Past 140 columns you may split it, but you are not required to. When you do split, use as few lines as possible: fill each line with operands up to 140 columns and break only at a top-level && or ||, which then starts the next line. The parentheses of "if (", "else if (" and "while (", and a pair that encloses the whole right-hand side of an assignment or return, are the opener, so the && or || directly inside them are the top-level break points and the operand aligns after the "if (", "else if (", "while (", "= (" or "return ("; never break inside any other parentheses. Count the closing ) and any terminating ; toward the line's columns, and let a single operand that cannot fit stand alone on its line even when it passes 140. Indent each continuation line with tabs up to the statement's own indent level and then pad with spaces so its operand starts in the same column as the first operand on the opening line, with "&& " or "|| " immediately to the left of that column — tabs for indentation, spaces for alignment, tabs counting as 4 columns. The exception is the same one stated above for arguments.

	Declaration (good):
	void CreateBuffer(std::string_view name, VkDeviceSize vkDeviceSize, VkBufferUsageFlags vkBufferUsageFlags, VkMemoryPropertyFlags vkMemoryPropertyFlags, VkBuffer& rVkBuffer, VkDeviceMemory& rVkDeviceMemory);

	Call (bad — arguments wrapped):
	engine::gpAudioManager->PlayOneShot3d(rFrame,
		data::kAudioMissileCrc,
		vecMissilePosition, gMissileLaunchVolume.Get(), gMissilePitchMin.Get(), gMissilePitchRandom.Get());

	Call (good — single line, however long):
	engine::gpAudioManager->PlayOneShot3d(rFrame, data::kAudioMissileCrc, vecMissilePosition, gMissileLaunchVolume.Get(), gMissilePitchMin.Get(), gMissilePitchRandom.Get());

	Declaration (bad — split at "="):
	std::shared_ptr<StaleUpdateState> pState =
		std::make_shared<StaleUpdateState>();

	Declaration (good — single line, however long):
	std::shared_ptr<StaleUpdateState> pState = std::make_shared<StaleUpdateState>();

	Lambda/struct exception (good):
	common::gpMultithreading->Dispatch(iCount, [&](int64_t i)
	{
		// ...
	});

	One-line initializer list (good — stays on the call line):
	return std::formatter<std::string_view>::format(common::FormatVector(pcBuffer, {f4.x, f4.y, f4.z, f4.w}), rContext);

	Condition (bad — wrapped although it joins to 122 columns):
	if (rSlot.eState == CoordSubscriptionState::kWaitingFullState
		|| rSlot.eState == CoordSubscriptionState::kSubscribing)

	Condition (good — joins to 140 or fewer, so one line):

	Condition past 140 (allowed split — greedy fill, leading operator, aligned):
	if (uiSlotIndex < std::ssize(pClient->slots) && (pClient->slots.at(uiSlotIndex).subscription.flags & SubscriptionFlags::kActive)
	 && pClient->slots.at(uiSlotIndex).ack.uiEpoch == uiEpoch)

	Assignment past 140 (same rules; alignment padding is spaces after the statement's tabs):
		bAcceptRawCpuTimers = iFullTicks == 1 && mTimeStep.miTimeMultiply == 1 && mTimeStep.miTimeDivide == 1
		                   && !(mGameFlags & GameFlags::kPaused) && !gpReplay->IsRecording() && !mbReplaying
		                   && !(mGameFlags & GameFlags::kSaveReplay);

56. Use complete words in all variable and function names. Do not abbreviate (e.g., `rReconcileContext` not `ctx`, `bufferIt` not `bufIt`, `rCommandBuffer` not `cmdBuf`). Exception: loop counters `i`/`j`/`k` and iterators `it` (per rule 8).

57. Do not use "Impl", "Internal", or similar non-word suffixes on function names. If a function reconciles, name it `Reconcile()`, not `ReconcileImpl()`. Use scope (a private member, or a `static` file-local function) to distinguish internal from public versions.

61. "if" and "else" bodies always use curly braces, even for a single statement (braces per rule 2):

	if (pLine[0] != '\0')
	{
		++iCount;
	}
	else
	{
		break;
	}

62. Use early returns for guard and validation sequences. When several unrelated conditions each guard the same single-statement exit, write one "if" per condition instead of packing them into one large "if (A || B || C)" disjunction. The same check over parallel values is one condition and may stay in one "if". Keep the conditions in their original order, grouped by concern; reordering them changes which condition is evaluated first:

	Bad (unrelated guards packed into one disjunction):
	if (pTarget == nullptr || !rFrame.mbSimulating || iProjectileCount == 0)
	{
		return;
	}

	Good (one early return per condition, original order kept):
	if (pTarget == nullptr)
	{
		return;
	}

	if (!rFrame.mbSimulating)
	{
		return;
	}

	if (iProjectileCount == 0)
	{
		return;
	}

	Good (the same validity check over two parallel results stays in one "if"):
	if (!bOneValid || !bTwoValid)
	{
		return false;
	}

63. Do not use XMVector3Rotate() or XMVector3InverseRotate() in "DirectX Math", they return a rounding-residue W that violates the W invariant (positions W=1.0, directions W=0.0). Both raw names are compile-poisoned in ExternalHeaders.h: Use XMVector3RotateSafe(), not XMVector3Rotate()

64. Comments describe the present code: the constraint, invariant, required ordering, or consequence the code as it now stands cannot say itself. Every statement a comment makes must be true of the code as it now stands, including any code elsewhere the comment names. Never describe the previous implementation, the change that produced the current code, or a comparison against replaced code:

	Bad (narrates the replaced implementation):
	// 258 XMVECTORs on the stack push this function past the 16 KiB the analysis build allows, so the origins
	// live in the workbuffer instead; its frames start 16-byte aligned, so XMVECTOR storage is safe there.

	Good (states the present constraint):
	// This function's locals must fit the 16 KiB stack budget the analysis build allows, so the 258 origins
	// live in the workbuffer; its frames start 16-byte aligned, so XMVECTOR storage is safe there.

A comment also never restates the signature or a house pattern in template fields (Parameters, Returns, Thread-safety), never uses banner separators, never merely explains a language feature or house pattern the declaration already shows, never carries an AGENTS.md navigation pointer as its content, never describes a hypothetical or future code path, and never argues that the code is correct:

	Bad (template fields restating the declaration):
	// Executes an external process with captured stdin/stdout/stderr and returns the output and exit code
	// Parameters:
	//   rExecutableFile - Full path to the executable to run
	//   rCommandLine - Command-line arguments (wide string). Modified by CreateProcessW so cannot be const
	// Returns: ExecutableResult containing combined stdout/stderr output and the process exit code
	// Creates pipes for process communication, runs the process with CREATE_NO_WINDOW flag,
	// captures all output until the process terminates or closes its output handles
	// Used by DataPacker to run build tools like glslangValidator and ffmpeg
	// Thread-safety: Thread-safe - uses local resources and process isolation

	Good (only what the declaration cannot say):
	// CreateProcessW writes into rCommandLine, so it cannot be const.

What a comment should say, in the fewest sentences that carry it: an invariant, a required ordering and the consequence of breaking it, a lifetime or threading contract, a platform, driver, or toolchain workaround, or a relationship to code elsewhere the local code cannot show. The rule 65 named-namespace closing comment is required, so rule 64 never reports it.

65. Close every named namespace with `} // namespace <name>` on its closing brace, with a nested name exactly as the opening declares it:

	Good:
	namespace engine::NetworkMessages
	{
	...
	} // namespace engine::NetworkMessages

66. Do not open an anonymous namespace. File-local functions, including `constexpr` functions and function templates, and file-local non-const variables are `static` in the file's named namespace, or at global scope where the file has none. File-local namespace-scope `const`/`constexpr` variables in a `.cpp` file already have internal linkage and take neither `static` nor `inline` (header globals keep rule 25's `inline constexpr`). A file-local type has external linkage, so its name must be unique among the files in the same executable and namespace.

67. A type declared with the "class" keyword keeps every member definition that is not in its header in one .cpp file; never split one class's member definitions across several .cpp files. Types declared with "struct" (including frame Collections) and free functions are exempt. Example: ClientSession.cpp defines every ClientSession member.

68. When an integer literal must have a specific fixed-width type, write it with the MSVC sized suffix: i64 for int64_t, ui64 for uint64_t, i32 for int32_t, ui32 for uint32_t, i16 for int16_t, ui16 for uint16_t, ui8 for uint8_t. Never spell such a literal as static_cast<T>(N), T{N}, or with an ll, LL, ull, ULL, u, or U suffix. A literal whose default int type is already what the expression needs stays unsuffixed. Two cases keep their cast: an int8_t literal keeps static_cast<int8_t>(N), because i8 is char, not signed char, and a cast to a named API alias or enum type (UINT, DWORD, VkImageCreateFlags, common::crc_t, an enum) stays a cast, because the name carries the meaning. A literal in a header compiled as both C++ and GLSL keeps its u suffix, because GLSL has no sized suffixes:

	Bad:
	std::iota(pRows, pRows + iCount, int64_t{0});
	iX = std::clamp(iX, static_cast<int64_t>(0), iMaximum);
	uint64_t uiBit = 1ULL << iIndex;

	Good:
	std::iota(pRows, pRows + iCount, 0i64);
	iX = std::clamp(iX, 0i64, iMaximum);
	uint64_t uiBit = 1ui64 << iIndex;
	kMouseButtonLeft = 1ui32 << 0,
