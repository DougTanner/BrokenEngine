# Name the DataPacker owning export job list

## Context

`DataPacker/Source/Main.cpp` repeats `std::vector<std::unique_ptr<T>>` eight times across six pipeline function signatures and two locals. These are the same owning list throughout discovery, sorting, generated CRC registration, and export publication. A translation-unit-only alias template makes that shared type easier to read while preserving the exact existing type and its performance.

Source evidence at baseline `d29fed456d3ede935c5e672f95f13d6733f0660c`: the repeated spellings occur at lines 70, 85, 341, 343, 416, 440, 499, and 610. The function and local names below are the implementation anchors if line numbers move. `Common/AlignedMemory.h:17` already demonstrates alias-template usage; `Documents/C++StyleGuide.txt` rule 23 already prefers `using` to `typedef`. No documentation or style-policy amendment is warranted for this implementation-local spelling change.

## Design

Immediately before `RegisterGeneratedCrcNames`, add a namespace-scope alias in `Main.cpp` only:

```cpp
template<typename T>
using ExportJobList = std::vector<std::unique_ptr<T>>;
```

Replace exactly the eight existing full container spellings with `ExportJobList<T>`. Preserve surrounding `const`, references, function template constraints, initializers, and all executable statements. Keep individual `std::unique_ptr<T>` declarations explicit, including loop elements, comparator parameters, and the reference returned by `emplace_back`. The alias is not a wrapper and adds no runtime operation, storage, or allocation; no speedup is claimed.
