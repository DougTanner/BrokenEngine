# Compact smoke dilation lists with optional subgroup ballots

## Context

The existing direct and remapped smoke dilation shaders reserve one global list slot per active tile. `Engine/Data/Shaders/Smoke/SmokeOccupancyDilate.comp:63` and `SmokeOccupancyDilateRemap.comp:76`, in `main`, each call `atomicAdd(uiDispatchX, 1u)`. Destination occupancy short-circuits the neighborhood search, so dense activity can expose contention without 25 intervening source loads. Spatially clustered plumes are a concrete current consumer for combining reservations. This is an expected performance improvement, not an already measured gain or a correctness defect. The user authorized this bounded optimization with measured retention criteria.

`ShaderLayoutsBase.h:175` uses 256 dilation invocations per workgroup. `BufferManager::CreateSmokeHierarchicalBuffers` allocates one list slot per tile. `SmokeSpreadOne.comp` and `SmokeSpreadTwo.comp` consume tile identities, not list order. Existing atomics already make order nondeterministic. A nonempty participating subgroup can reserve K slots once instead of K individual reservations; this does not predict a K-fold speedup. Driver aggregation, register pressure and ballot overhead can erase the benefit.

## Design

Recommended design: retain the current direct-atomic modules as the unsupported-device path and add exactly two ballot modules. This preserves Vulkan 1.2 and the current supported-device set while limiting selection machinery to one capability result and two CRC checks. All choices below are the author's recommended implementation, with acceptance deciding retention.

1. In `InstanceManager::ValidatePhysicalDeviceCapabilities`, replace its selected-device ordinary property query with `VkPhysicalDeviceProperties2` chained to local `VkPhysicalDeviceSubgroupProperties`; copy the returned ordinary properties into the existing `mVkPhysicalDeviceProperties`. Add `bool mbSmokeSubgroupBallot = false` to `InstanceManager`. Set it from compute-stage support and both `VK_SUBGROUP_FEATURE_BASIC_BIT` and `VK_SUBGROUP_FEATURE_BALLOT_BIT`. Query after final physical-device selection, refresh on full recreation, and log the selected path once. Do not change device scoring, required features, logical-device enables, or the API version.
2. Keep `SmokeOccupancyDilate.comp` and `SmokeOccupancyDilateRemap.comp` as baseline entry points. Add `SmokeOccupancyDilateBallot.comp` and `SmokeOccupancyDilateRemapBallot.comp`. Move each corresponding algorithm and declarations into `SmokeOccupancyDilateBody.h` and `SmokeOccupancyDilateRemapBody.h` under the same Smoke directory. Each entry point keeps `#version 460`, sets `BT_SMOKE_SUBGROUP_BALLOT` to 0 or 1 and includes its body. Only ballot entry points require `GL_KHR_shader_subgroup_basic` and `GL_KHR_shader_subgroup_ballot`. Share the actually duplicated append operation in `SmokeOccupancyAppend.h`, included after the list buffer declaration. Do not merge the direct and remapped neighborhood algorithms.
3. Compute `bActive = false` initially; execute all tile-coordinate, occupancy and remap accesses only inside the valid-tile branch. Remove the early out-of-range return so every live boundary invocation reaches the append call with a false predicate. Preserve the existing neighborhood predicate, short-circuiting, remap arithmetic and stale-destination union. Baseline append remains `if (bActive)` plus one atomic and write. Ballot append forms `subgroupBallot(bActive)`, obtains `subgroupBallotBitCount` and `subgroupBallotExclusiveBitCount`, elects one invocation to reserve that count when nonzero, and distributes its initialized reservation base with `subgroupBroadcastFirst`; only active lanes write base plus rank. Empty masks perform no atomic. Keep ballot/count/rank/election/broadcast together outside the divergent neighborhood search; never assume subgroup size, full participation or lane-to-pixel adjacency. Election may choose an inactive tile invocation, which is valid because it reserves for the participating active tiles.
4. Before accepting that sequence, prove from Vulkan/SPIR-V rules and the optimized modules that elected reservation and broadcast cover the same participating invocation set, including divergence and partial workgroups. Use dynamically participating sets rather than assuming workgroup-wide reconvergence. Require no subgroup-uniform-control-flow extension, subgroup-size control, shuffle family, dynamic broadcast ID feature, or fixed subgroup size. If the stated BASIC/BALLOT design cannot meet that proof, reject this optimization rather than introducing another feature requirement or framework.
5. `PipelineManager::PipelineManager` currently eagerly calls `mShaders.try_emplace`, and `Shader::Shader` calls `vkCreateShaderModule`. Skip exactly the two ballot CRCs when `mbSmokeSubgroupBallot` is false, before Shader construction. Keep existing pack validation for constructed modules. In the same constructor's `SmokeOccupancyPipelineDescription` array, select baseline or ballot CRCs using that same result. Preserve pipeline enum values, descriptors and names. Rebuilding pipelines repeats selection; full device recreation refreshes capability first.
6. Ordinary `ExportShader::Handles`, `PreprocessShader`, `CompileShader`, `OptimizeShader` and reflection already discover `.comp`, track includes, target Vulkan 1.2 and generate path CRCs. Use that unchanged route to generate `kShadersSmokeSmokeOccupancyDilateBallotcompCrc` and `kShadersSmokeSmokeOccupancyDilateRemapBallotcompCrc`. Re-export local shader assets before building consumers of the generated header. Verify include edits invalidate all dependent modules and a second unchanged export is clean. No pack layout or format version changes are needed: only shader assets and generated content change.

## Acceptance criteria

### Correctness and compatibility

- Build through `/compile`: Local DataPacker Release export and optimized client Release; validate actual packed baseline and ballot SPIR-V against Vulkan 1.2. Baseline modules contain no optional subgroup capabilities; ballot modules require only the stated subgroup families. Reflection matches existing layouts. Verify generated CRC identities, incremental include invalidation and clean repeat export.
- Through `/agent-harness`, compare original optimized baseline, final baseline forced by a temporary build-only false capability assignment, and automatic ballot selection. Instrument or break at `Shader::Shader`/`vkCreateShaderModule` to prove neither ballot module is constructed in forced fallback; no permanent override remains. On genuine unsupported hardware, run startup and the ordinary scene if available; disclose absence as a hardware coverage gap, never claim emulation proves that device's driver behavior.
- For both direct and remapped dispatches, capture/read back immutable inputs and output lists. Independently compute the documented 5x5 predicate from those inputs in temporary capture analysis; compare sorted list indices and counts, require every expected tile exactly once, all indices below tile count, count at most capacity, and unchanged indirect Y/Z. Compare exact output texture bytes after each spread half with identical captured inputs/time uniforms; unordered tile scheduling must not change them.
- Exercise tile counts 1, 31, 32, 33, 255, 256 and 257 in capture replay with matching buffers/uniforms, including non-square grids; empty, all-active, alternating, single first/last tile and destination-only occupancy masks. Run on available devices exposing subgroup sizes 32 and 64; both sizes are required for retention. No forced subgroup size or assumption that these exhaust supported sizes enters production code.
- Exercise stationary view, pan by one tile and beyond the view width, zoom inward/outward across a resolution transition, enable/disable, clear, deposit cessation through exact-zero extinction, pipeline recreation and full device recreation. Check both ping-pong images and lists; extinction reaches zero on the same frame for identical replayed render inputs. Vulkan validation reports no new errors. Existing barriers, list capacity, record-once commands and client-only CRC exclusion remain unchanged.

### Measured retain/revert gate

These are recommended usefulness thresholds, not measured results. Record GPU/driver, clocks/power mode, subgroup size, build and pack hashes, scene/camera input files, resolution and raw samples in the verification report. Use at least two capable GPU architectures spanning subgroup sizes 32 and 64. Missing required benchmark hardware leaves retention unproven; do not substitute a dense-only result or expand the change to device-specific policy.

Use optimized baseline and candidate with identical settings, fixed render delta and recorded smoke deposits/camera path, VSync off, after 300 warmup frames. Collect ten paired runs of 1,800 frames per workload, alternating baseline/candidate order. Do not time correctness readbacks. Use GPU capture timing for each dilation dispatch and the existing `kGpuTimerSmokeSpread` for the full two-half spread; additionally report all smoke GPU work including deposits/clears, whole-frame GPU time, and CPU frame time. Capture timing must be paired under identical instrumentation; assess aggregate timings without capture overhead too.

| Workload | Exact definition |
|---|---|
| Empty | Zero occupancy throughout; no deposits; stationary camera. |
| Sparse | Separated deposits adjusted in setup to keep post-dilation coverage between 1% and 5%; stationary camera. |
| Clustered | Four separated plumes maintaining 20%-40% post-dilation coverage; stationary camera. |
| Dense | Sustained deposits maintaining 90%-100% post-dilation coverage; stationary camera. |
| Gameplay mix | Fixed 1,800-frame trace: 600 sparse, 600 clustered, 600 deposit-off decay frames; in each block 200 stationary, 200 panning one view-width, 200 zooming out then back. Record achieved occupancy each frame. |

Run each workload at 1920x1080 and 3840x2160 window extents with the same default smoke-quality setting; record actual smoke texture/tile extents because these need not scale with the window. Synthetic occupancy setup belongs to capture replay or temporary harness-driven scene setup, not a production feature.

Retain only if all correctness criteria pass and, on each tested GPU at both extents: (a) the sum of the two dilation median GPU durations improves by at least 10% for clustered and dense workloads; (b) gameplay-mix total smoke median improves by at least 3% and 0.02 ms; (c) each improvement's paired 95% confidence interval excludes zero; and (d) no workload's median or p95 total smoke time regresses beyond the larger of 2% or 0.01 ms, nor whole-frame GPU/CPU beyond the larger of 1% or 0.05 ms. Derive intervals over independent paired-run summaries, not correlated individual frames. Report dispatch-level median/p95 even when only their sum gates retention. The 10% gate excludes marginal instruction reshuffling; the aggregate absolute floor justifies maintaining two additional modules; the regression allowances absorb small timing noise without accepting a sparse/empty penalty.

If any required measurement fails, remains noise-level, or compiler/driver inspection shows equivalent atomic aggregation without these aggregate gains, remove the entire production optimization, additional assets and capability plumbing. Keep the baseline and report the measured rejection; do not land a dormant path or relax thresholds after seeing results. If verification cannot be completed, report that blocker and leave the optimization unaccepted.
