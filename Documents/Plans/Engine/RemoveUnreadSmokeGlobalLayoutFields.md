# Remove the GlobalLayout smoke fields no shader reads

## Context

`shaders::GlobalLayout` (`Engine/Data/Shaders/ShaderGlobalLayout.h`) is the
CPU/GLSL-shared global uniform block. Three of its fields have no GLSL reader:

- `fSunIntensitySmoke` and `fMoonIntensitySmoke` (`ShaderGlobalLayout.h:31-32`)
- `fSmokeLightingMultiplier` (`ShaderGlobalLayout.h:71`)

Their only shader reader was the `BlendSmoke` helper in
`Engine/Data/Shaders/ShaderFunctions.h`, which had no caller and was deleted by
the change that also gave `AddSmoke` and `BlendSmokePrecomputed` their
`fObjectShadow` parameter. The surviving smoke helpers read the CPU-folded
products `f4SmokeBaseLighting` and `fSmokeLightingCombinedMultiplier` instead.
A search of the whole repository for the three names finds no other GLSL read
and no C++ read of the layout fields; only these writes remain:

- `Engine/Source/Graphics/Render/GlobalUniforms.cpp:153-154`
  (`PopulateDayCycleColors`) copies the locals `fSunIntensitySmoke` and
  `fMoonIntensitySmoke` (declared at lines 149-150) into the layout. The same
  locals already fold `f4SmokeBaseLighting` at line 174.
- `Engine/Source/Graphics/Render/SmokeUniforms.cpp:60` (`RenderSmokeGlobal`)
  writes `gSmokeLightingMultiplier.mfCurrent` into the layout.
  `PopulateSunAndLighting` (`GlobalUniforms.cpp:241`) folds
  `fSmokeLightingCombinedMultiplier` straight from
  `gSmokeLightingMultiplier.mfCurrent`, not from the layout field.

Originating gap: a dead CPU/GPU uniform field left behind when its last shader
reader was deleted. Removing it was deferred here because it changes the shared
uniform layout, which the originating change's tier excluded.

## Design

The author recommends deleting the three fields and their writes, keeping the
CPU-side values where they are already used:

- Delete the three field declarations from `GlobalLayout`. GLSL and C++ both
  take the struct from this one header, so field offsets stay in agreement.
- Delete the two layout writes at `GlobalUniforms.cpp:153-154`; the locals at
  lines 149-150 stay and still fold `f4SmokeBaseLighting`.
- Delete the layout write at `SmokeUniforms.cpp:60`; no local is needed, since
  `PopulateSunAndLighting` already reads `gSmokeLightingMultiplier` directly.
- Correct the comments these removals make false: the per-target intensity
  comment at `ShaderGlobalLayout.h:29-30` and `GlobalUniforms.cpp:143-144`
  (each says Smoke remains a raw multiplier), and the
  `GlobalUniforms.cpp:239-240` comment naming the `fSmokeLightingMultiplier`
  layout field as the source written by `RenderSmokeGlobal`. The
  `f4SmokeBaseLighting` and `fSmokeLightingCombinedMultiplier` field comments
  (`ShaderGlobalLayout.h:41`, `:53`) name the operands that were folded; reword
  them only where they would name a removed layout field rather than the
  CPU-side value.

Change Workflow tier: Tier 3. Trigger: data layout — the change alters the
CPU/GPU-shared `GlobalLayout` uniform layout
(`.agents/references/risk-tiers.md` `### Risk tiers`).

Exposure:

- Shader: every shader including `ShaderLayoutsBase.h` sees the new offsets, so
  the SPIR-V must be regenerated by DataPacker together with the client build;
  a client run against shaders packed before the change reads shifted fields.
- Determinism/CRC, wire, replay, save, `.pack` format version: none.
  `GlobalLayout` is client render state only, outside the CRC, and never
  serialized or sent.
- Affinity: the header is consumed by client and server builds
  (`Engine/Data/Shaders/AGENTS.md` `## Shared Contract`); only client code
  writes the fields.

## Critical files

- `Engine/Data/Shaders/ShaderGlobalLayout.h`
- `Engine/Source/Graphics/Render/GlobalUniforms.cpp`
- `Engine/Source/Graphics/Render/SmokeUniforms.cpp`

## In scope

- `GlobalLayout` members `fSunIntensitySmoke`, `fMoonIntensitySmoke`, and
  `fSmokeLightingMultiplier`, and the comments at `ShaderGlobalLayout.h:29-30`,
  `:41`, and `:53` that describe them.
- `PopulateDayCycleColors` in `GlobalUniforms.cpp`: the two layout writes and
  the intensity comment above the locals.
- `PopulateSunAndLighting` in `GlobalUniforms.cpp`: the smoke lighting
  multiplier comment only.
- `RenderSmokeGlobal` in `SmokeUniforms.cpp`: the `fSmokeLightingMultiplier`
  layout write.

## Out of scope

- The tuning variables `gSunMoonSunIntensitySmoke`,
  `gSunMoonMoonIntensitySmoke`, and `gSmokeLightingMultiplier`, and the folded
  fields `f4SmokeBaseLighting` and `fSmokeLightingCombinedMultiplier`: they stay.
- Any other `GlobalLayout` field, including `fLightingTimeOfDayMultiplier`,
  `f4SunColor`, `f4MoonColor`, and `f4AmbientColor`, which still have GLSL
  readers.
- Any change to smoke lighting math or to the smoke helpers in
  `ShaderFunctions.h`.

## Acceptance criteria

- The three names no longer appear as `GlobalLayout` members or layout writes
  anywhere in the repository.
- The BrokenEngineSandbox client and server build, and DataPacker compiles every
  shader, through `/compile`.
- Smoke renders as before the change in a live client run through
  `/agent-harness`; the evidence behind this Plan records no harness setup, so
  the executing session chooses one that shows smoke on screen.

## Notes

- Removing a field shifts every later `GlobalLayout` offset; no field is
  reordered, so scalar-layout alignment rules are unaffected.
