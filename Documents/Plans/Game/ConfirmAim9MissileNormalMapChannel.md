# Confirm the aim-9_missile normal map channel

## Context

`Projects/BrokenEngineSandbox/Data/Models/aim-9_missile/textures/lambert1_normal.png`
carries a green inversion chosen by inference, as the `PROVENANCE.md` beside it
states. If the inference is wrong, every fastener on the game's missile model
renders with its relief inverted. aim-9_missile is that model (`kMissileModelCrc`,
`Projects/BrokenEngineSandbox/Source/Frame/Collections/Missiles/MissilesRender.cpp:13`).

The curl test: a height-field normal map is curl-free, so red and green must
agree about the image axes. Decode both to -1..1, reconstruct blue from unit
length (0.1 where its square is at most 0.01), and take p = red/blue and
q = green/blue. Over covered texels, using central differences and dropping
texels where either difference exceeds 0.5, correlate dp/d(row) with dq/d(column).
Positive means green runs +row, which is +V in raw glTF UV. It sees only the
relative sign of red and green.

The scene's authored bitangent runs +V on 100.00% of corners, and h, the UV
handedness sign, is +1 on 1692 of 1700 triangles. As supplied, the map measured
-0.3811 against that frame, with 71.8% of its curl energy in opposed tiles, 0.1%
in agreeing tiles and 28.1% in neutral tiles. Its fasteners gave a direct
signature: 29 of 29 bright blobs with relief showed slope signs (+,-), with mean
red +0.508 and mean green -0.485.

Relative to a +V frame, (+,-) has two readings, which differ by a global relief
sign the curl test cannot see:

- Raised fasteners with green flipped. Then the current map is right, at (+,+).
- Recessed fasteners with red flipped. Then the frame-correct map is (-,-), and
  the current map has both channels opposite to it.

Green was chosen because (red +column, green -row) on raised relief is exactly the
glTF encoding, so that reading needs no channel to be defective; SeaCreature2
matches it, and no map with a usable geometry signal shows red along -column. That
is inference, not proof.

Nothing in the tree settles it. The scene has no occlusion map, only
`lambert1_baseColor.jpeg`, `lambert1_metallicRoughness.png` and the normal map.
The render regression gives no absolute verdict: with bright base color taken as
raised, the coefficients along T and B are -0.549, -0.163 stored, -0.546, -0.116
green inverted and -0.661, -0.156 red inverted, a fixed offset that comes from
painted base color, leaving each channel a contribution of only +0.056 and
-0.024. Base-luma slope is not calibrated: RavenStarConflictV2 gives +0.33, -0.38
although its curl and geometry both say (+,+).

The inversion reaches the render: against the supplied map, 1946 model mask pixels
move above noise floor 2 (noise 0) and 325 above floor 8.

## Design

The author's recommendation is two steps, in order.

First, find an independent height truth for the fasteners through
`/external-diagnose-bug`. Candidate sources, in the order the author would try
them: the source page and author named in the scene's `license.txt`, reference
photographs of the fasteners on the real missile, and painted cavity shading in
`lambert1_baseColor.jpeg` once that predictor is calibrated on sibling maps whose
relief sign geometry shows. If none settles it, stop, leave the map as it is, and
report that no truth was found.

Then act on the result. If the fasteners are raised, the map stays and
`aim-9_missile/PROVENANCE.md` replaces its inference sentence with the confirmed
source. If they are recessed, invert both red and green of the current map, which
restores supplied green and inverts red, keeping it 8-bit RGB at its size with
blue byte-identical, let the ordinary export regenerate the tracked intermediates,
and record that in `PROVENANCE.md`.

A fix outside the map stops for re-planning instead of widening scope.

## Out of scope

No change to any shader, DataPacker, `scene.gltf`, `scene.bin`, `license.txt`, or
the scene's other textures. No edit to any other scene or map. No new fixture
model, harness command or unit test.

## Acceptance criteria

- `/external-diagnose-bug`'s result names the height truth and its source, or
  states that none was found.
- The recorded symptom no longer reproduces: with a truth found,
  `PROVENANCE.md` no longer calls the channel an inference. With none found, the
  map and `PROVENANCE.md` are byte-identical and the result is reported.
- If the map changes, the curl test still gives +0.3811 to within 0.01, the 29
  fasteners measure (-,-), and red and green each equal 255 minus the prior value
  on every texel.
- If the map changes, the scene exports through the ordinary DataPacker scene
  export via `/compile`, and a capture returns code `ok` with no `DEBUG_BREAK at`
  in the log.
- The diff touches only the files `## In scope` names.

Live setup, in order, as the observing runs recorded it: `/compile`
`-Target ModelViewer -Configuration Debug`, whose summary counts only when it
shows `RunDataPacker=true` and the worktree `GameDataDirectory`, then one
`/agent-harness` ModelViewer capture with `-ModelPath`
`Models\aim-9_missile\scene.gltf`, a PNG at the viewer's fitted framing and
exposure 1.0. The supplied evidence records no setup for viewing the missile in a
game session; establish and record it during execution if the map changes.

## Notes

Future implementation is Tier 2: trigger is one subsystem's runtime behavior, the
rendered output of one tracked model, with no format or layout change. It would
change the look of the game's missile model.

Texture bytes change and formats do not, so there is no serialization change or
`kiVersion` bump. Model shading is outside PostRender state, so determinism/CRC,
replay, wire, threading and allocation are unaffected, and no shader or C++
changes.
