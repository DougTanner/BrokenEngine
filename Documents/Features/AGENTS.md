# Features

Ideas saved for another day, whether or not the design is decided. Feature plans are tracked Markdown documents, but execution is manual: WorktreeCli never validates, claims, stores locks for, or changes `Documents/Features`.

Use existing subject-area subdirectories and retain clear scope, invariants, and acceptance criteria. Work wanted soon belongs in `Documents/Investigations` until it is decision-complete, then in `Documents/Plans`, the only tree covered by `/next-plan`.

A design deferred because it is not needed yet keeps a `Revisit When` line naming the concrete trigger that would make it worth doing, so a later reader can tell a rejected idea from a waiting one. The `Frame/Future*.md` documents are the pattern.
