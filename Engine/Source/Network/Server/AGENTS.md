# Network Server - Host, Slots, and Resends

Server-only engine transport. `Server` (`gpServer`) owns the ENet host, client transport records, subscription slots, update rings, and resend state, plus client-to-server admission and violation accounting for engine and game packets, including handler throws. `ServerSessionRuntime` owns host lifetime, fixed-tick pacing, discovery, poll/tick/paused sequencing, queue servicing, broadcast consumption, resend, flush, and transport reset. `OwnedEntityRegistry` owns per-client owned-entity records and keeps their `authorizedCoords` mirror index-parallel. The game server session (`../../../../Projects/BrokenEngineSandbox/Source/Network/Server/AGENTS.md`) supplies game packet contracts and dispatch, authorization, transfer payloads and classification, and gameplay hooks.

## Affinity and Lifetime

- This directory is server-project-only and every source/header remains whole-file `BT_SERVER` guarded.
- ENet host service, compression scratch, queues, and delayed-packet simulation are main-thread-owned.
- Disconnect purges delayed packets for that peer before its transport state can be reused.

## Session Invariants

- Accept a client only after protocol, Frame version, and ordered island-manifest identity pass. Repeated Hello preserves the stored GUID; mint a GUID only for a first accepted client that supplied none.
- `Server` owns the current debugging-load generation and stamps connection bootstrap and all load-scoped subscription traffic. It rejects a subscription request whose generation differs from the current world after finding the handshaken client and before coordinate lookup, slot allocation, or publication. The game load-reset hook advances the generation before notification, slot clearing, or reset-state mutation. Wire width, exhaustion, and client behavior: [Network architecture](../../../../Documents/Architecture/Network.md#debug-load-generation).
- Run the client-to-server contract gate before dispatch for engine and game packets. Variable payload handlers parse into bounded local state before mutation; contract violations, including game handler throws, use the central accounting/disconnect path.
- `RecordContractViolation` can destroy the client record: at `kiContractViolationDisconnectCount` it pushes the pending disconnect itself, so the game layer still gets the notification, then disconnects the peer and removes the record. Treat the call as the last use of that `ClientConnection*` — read what you still need before it and return immediately after, or the next line reads freed memory on a path hostile client input can reach.
- Each client admits one desync report and one debug-frame request per two seconds of `steady_clock` time after contract validation; immediate repeats within the per-update cap are silent, and over-cap traffic keeps the contract-violation policy. A disabled-build debug-frame request stays contract-valid, starts its cooldown, then returns without parsing, logging, lookup, compression, or sending.
- After each complete `AfterNetworkPoll()`, `ServerSessionRuntime` samples the engine client set and updates its presence tracker unconditionally; it clears network-driven pause and writes 1:1 timescale only on the sampled nonempty-to-empty transition and only when the ratio differs, so an already-empty server keeps its commanded pause/timescale.
- Each update polls twice, at update start and at the tick boundary after the fixed-tick wait, so commands that arrived during the wait enter the imminent tick. The boundary poll deliberately omits `BeforeNetworkPoll`, which clears the previous update's pending request queues, and continues the first poll's admission budget window: one budget window per update, not one per poll.
- The fixed-tick wait consumes the carried tick remainder but does not maintain it; `TimeStep::TickRealtime`, which `GameBase` calls immediately after the wait, accumulates and wraps it. Preserve the `siTotalTicks`/`siOvershootTicks` counters and their profiling-gated verbose log when changing this path.
- Poll-scoped requests drain each poll: the handler that processes a fleet request queue drains it, so a second poll in the same update cannot reprocess it. Deduplicate the new-subscription and resync requests that persist per [Timing and Polling](../AGENTS.md#timing-and-polling) while pending.
- `ServerSessionRuntime` owns the active coordinate set — subscribed coordinates plus the coordinates the game session contributes, always including origin. It creates a Frame for each entering coordinate and hands ownership of each departing current Frame to the game hook before erasing the coordinate storage; the game server contract owns that hook's forwarding obligation.
- A subscription must be origin or adjacent to an authorized coordinate. Subscription, ACK, and resend-log bookkeeping stay together per slot; allocation stays within the client-supported count, and reuse increments rather than resets the epoch.
- After existing-client lookup, unsubscribe ACKs every syntactically valid request and frees only an in-range active slot whose epoch matches the request.
- Clamp ACK floors to buffered history and otherwise require them to advance. The one exception is the backward floor a client produces by adopting a coord full state: sending that full state arms it per slot, and it is admitted only down to that full state's own tick and only while the tick stays within a bounded window of the latest buffered tick. Treat an all-zero ACK field as latency, not a resend gap, and cap resends per slot per tick.

## Transfers and Publication

- `ServerTransferManager` owns cross-cell transfer harvest, adjacency and destination-liveness validation, deterministic type ordering, and destination materialization. `ServerBroadcaster` owns the broadcast snapshot of a tick's status changes, the drain of agent-injected changes held for a later tick, and the per-coordinate publication `ServerSessionRuntime` hands to the delta resend ring at tick completion.
- Keep every workbuffer-backed publication view valid until synchronous delta and optional full-frame buffering have consumed it. Preflight capacity for the complete publication block before forming any view, including the codec-owned maximum nested compression scratch; update that maximum whenever status compression adds or enlarges workbuffer reservations.
- A transfer destination must be adjacent. A non-player transfer requires a destination that is already live; a player transfer makes its destination live.
- Recompute each destination Frame's `sharedCrc` after applying arrived transfers: the frame tick computes it before transfers land, and clients check their own simulated frame against the broadcast CRC for that tick, so skipping the recompute desyncs every client receiving a transfer. This is not defensive recomputation and must not be optimized away as redundant.
- Both classes name `game::StatusChange` and read, create, and pass whole game Frames and their state, such as `postRender.transferRequests` — a deliberate exception to the engine/game contract, because the payload crossing a cell boundary is game-defined while the machinery moving it is not. Player identity is not part of that exception: it goes through the engine ownership layer (`../../Frame/AGENTS.md`). Their headers therefore stay out of the `Engine.h` aggregation and consumers include them directly.
- Pending subscription updates stay on `game::ServerSession`; fixture queues come from the [game Agent's session-bound state](../../../../Projects/BrokenEngineSandbox/Source/Agent/AGENTS.md#contracts). The broadcaster drains injected changes before its tick snapshot and the transfer manager drains fixture transfers after natural collection and before deterministic sorting; each manager's reset clears only the fixture queue it drains. Each accepted transfer batch goes to the engine replay owner before live application (`../../File/AGENTS.md#replay-streams`); capture failure invalidates recording but never vetoes the accepted batch.

## Buffered State

- Buffer exactly one delta entry per supplied coordinate per tick in monotonically increasing order; resend lookup depends on contiguous tick offsets. With game `kbDesyncDebugFrames` enabled, also buffer the separate full-frame diagnostic ring. Clear both rings across save-load tick resets, and prune from the coordinates actually supplied to `BufferFrame`, not from simulation membership, so a replay coordinate published before it joins the dispatch set keeps its buffer.
- When an active slot's coordinate delta ring restarts after a gap, send the current authoritative full state before any delta or resend and hold both update paths until an accepted matching-epoch ACK reaches the pending full-state tick. A further restart while held supersedes the target with its newer tick; reuse an existing same-tick full state instead of sending a duplicate. Initial subscriptions, continuous rings, and ordinary explicit resync keep their existing ACK behavior.
- Preserve ring contiguity even when an update payload cannot be encoded; the resulting client CRC mismatch drives resync.
- Revalidate client, slot index, the slot's active flag, and coordinate immediately before sending a deferred full state because an unsubscribe or disconnect may have invalidated it in the same poll batch.
- Full-state resync and load notification are transport mechanisms; game state reconstruction remains game-owned.
